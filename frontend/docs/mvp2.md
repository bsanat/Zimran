# MVP 2.0 — совместные планы и уведомления

Реализованы четыре гостевых сценария из технического задания: подбор по тексту, Event Buddy, Pair Planning и Premium alerts. Интерфейс использует существующие цвета, Montserrat, карточки и кнопки проекта. Интерфейс доступен только на английском языке.

## Как проверить

Запустите `npm run dev`, откройте `/premium` и нажмите Try Premium Demo. Оплата не подключена: тариф $9.99/month показан как проверяемая гипотеза, демо не списывает деньги и не продлевается. Доступ проверяется сервером для каждой гостевой сессии.

- `/assistant`: чат вместо формы фильтров. Напишите `NYC, free games this Thursday` — реальные события, ссылка на детали и официальная ссылка появляются сразу в ответе. Можно начать с `New York`, затем уточнить `games this Thursday` и `free only`: город, интересы, даты и бюджет сохраняются в контексте. Чат уточняет недостающие или неоднозначные условия, а при отсутствии совпадений честно предлагает изменить запрос. Enter отправляет, Shift+Enter добавляет строку. История сохраняется в текущей вкладке; New chat начинает новый диалог. Используется локальный разбор текста на английском, русском и казахском, без внешнего LLM. Гостю доступен один успешный чат за семь дней, Premium Demo — до 50 новых чатов за сутки. В одном чате можно получить до 30 подборок в течение 24 часов, уточнения не расходуют новую недельную попытку.
- `/pair/new`: имя, New York, Games, даты на ближайшие 30 дней, любой бюджет и любое время. Создайте приглашение и откройте Open partner's window. Во втором окне укажите независимые предпочтения, поставьте Like на одном событии с обеих сторон. Итог сохраняется. Приглашение одноразовое, действует 48 часов, закрытие плана отзывает его. Без Premium можно создать один пробный план.
- `/buddy`: выберите событие, создайте демо-заявку с подтверждением 18+. Во втором независимом окне включите Premium Demo, откройте то же событие, отправьте отклик. Автор может принять или отклонить его; участник — отменить отклик. Доступны закрытие, Report и Block. Реальных профилей, проверки личности и личных контактов нет; публичные email, телефоны, ссылки и social handles запрещены.
- `/settings/alerts`: выберите Games, New York и Instant, сохраните. На `/notifications` нажмите Check new events. Проверенные события вводятся в отдельную демо-ленту, основной каталог не меняется. Совпадения создают уведомления с отметкой Demo; другая категория — нет. Повторная проверка не дублирует одно событие. Mark as read уменьшает счётчик, Pause alerts останавливает новые оповещения.

Приглашение следует открывать в отдельной вкладке через предоставленную ссылку с `noopener` либо в другом браузере. В одной вкладке сохраняется одна роль. Если браузер запрещает sessionStorage, роль живёт в памяти до перезагрузки.

В каталоге есть не все сочетания категорий, городов и дат. Например, Music + New York может вернуть пустой результат. Неизвестная цена не считается нулевой. Запись без подтверждённого времени не проходит конкретный фильтр morning/afternoon/evening. Пары используют пересечение дат и времени, меньший из двух бюджетов и только реальные ID каталога; несовпадение интересов отмечается как компромисс.

## API и хранение

Существующие `/api/events`, `/api/plan`, `/api/health` сохраняют интеграцию с `API_PROXY_ORIGIN`. Новые `/api/ai/*` и `/api/demo/*` обрабатываются локально; текущий внешний backend их не обязан поддерживать.

Каталог принимает необязательный `GET /api/events?budgetMax=25` в USD: `0` — только известная бесплатная цена, отсутствие параметра — без ограничения. Фильтр применяется до пагинации вместе с городом, датой и категорией. Внешний events backend должен поддержать этот параметр при подключении через proxy; в SerpApi live-поиске выбор бюджета отключён.

`POST /api/demo/session` выдаёт случайный токен. Браузер передаёт его в `Authorization: Bearer ...`, хранит в sessionStorage отдельной вкладки. На сервере сохраняется только хэш. Ответы имеют `Cache-Control: no-store`. Подписка, авторство заявок, участие в паре и право читать уведомления проверяются на сервере; изменение клиентского JS не выдаёт доступ. Ограничены размеры запросов, длина текстов и частота действий.

Основные локальные API:

| Путь | Действия |
| --- | --- |
| `/api/ai/chat` | POST сообщения с preferences, pendingFields и необязательным серверным conversationId; ответ с уточнениями или готовыми событиями |
| `/api/ai/parse`, `/api/ai/recommend` | Сохранённые POST разбора и подбора для совместимости |
| `/api/demo/subscription` | GET состояния; POST activate/deactivate |
| `/api/demo/buddy/posts` | GET списка; POST публикации |
| `/api/demo/buddy/posts/:id/requests` | POST отклика |
| `/api/demo/buddy/requests/:id/decision` | POST ACCEPTED/DECLINED |
| `/api/demo/buddy/requests/:id/cancel` | POST отмены |
| `/api/demo/buddy/posts/:id/close`, `/api/demo/safety` | POST закрытия, жалобы или блокировки |
| `/api/demo/pair/sessions`, `/api/demo/pair/join` | POST создания и присоединения |
| `/api/demo/pair/:id`, `/votes`, `/close` | GET состояния; POST голосования/закрытия |
| `/api/demo/alerts/preferences` | GET/PUT настроек |
| `/api/demo/alerts/check` | POST проверки демо-ленты |
| `/api/demo/notifications`, `/:id/read` | GET списка; PATCH прочтения |

Демо-данные сохраняются атомарно в `.outly-demo/state.json`, каталог исключён из git. Для изолированных проверок можно задать `OUTLY_DEMO_DIR`. Это постоянное хранилище одного локального сервера с доступным для записи диском. Перед несколькими процессами или serverless-развёртыванием нужен общий транзакционный backend; JWT, Supabase Auth и реальная подписка здесь не имитируются.

Daily/Weekly откладывают доставку на 24 часа/7 дней. После наступления срока уведомления видны при запросе центра уведомлений. Отдельного cron, email, Stripe и внешнего AI нет. При паузе или завершении Premium Demo отложенные доставки отменяются, уже доставленная история сохраняется. Интерфейс обновляет социальное состояние каждые пять секунд, счётчик уведомлений — каждые 15 секунд в активной вкладке.

## Проверки

`npm test`, `npm run typecheck`, `npm run build`. Тесты новых сценариев находятся в `tests/social.test.ts`, `tests/assistant.test.ts` и `tests/demo-api.test.ts`.

Проверка 14 ноября 2026: 68 автоматических тестов прошли. В браузере пройдены текстовый поиск с реальным результатом, две независимые роли Pair и взаимный Like, публикация/отклик/принятие Buddy, сохранение настроек после reload, создание уведомления, отсутствие дубля и уменьшение unread count после прочтения. Проверены RU/KK переключение, все шесть новых разделов на 320px и бюджет каталога на 320/375/1440px; ошибок JavaScript и горизонтального скролла не обнаружено.

После замены формы помощника на чат: 84 теста, production build и typecheck проходят. В браузере проверены диалог из нескольких сообщений, уточнение бюджета без второй недельной попытки, прямое открытие деталей события, официальные ссылки в ответе, сохранение истории, пустая выдача и повтор после сетевой ошибки без дублирования сообщения. Чат проверен на 320/375/768/1440px и при переключении RU/KK.

Публикация, push, реальные платежи, email и подключение внешних аккаунтов не выполнялись.
