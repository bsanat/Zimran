# Outly USA Frontend

MVP 2.0: добавлены текстовый Assistant, Event Buddy, совместные планы по приглашению, Premium Demo и персональные in-app уведомления. [Сценарии проверки, API и ограничения](docs/mvp2.md). Существующий каталог и Planner сохранены.

Фронтенд MVP по ТЗ Business Cup: гость выбирает интересы, дату и бюджет в New York, получает рекомендации от API и переходит к деталям реальных событий. Next.js App Router, TypeScript, React и Tailwind CSS 4. Интерфейс доступен на русском (по умолчанию), английском и казахском. Язык можно сменить в шапке; выбор сохраняется в cookie. Названия и описания событий отображаются на языке источника.

Реализован объём FE-01–FE-07: общие стили и навигация, главная, четырёхшаговый Planner, результаты, Explore с фильтрами и пагинацией, детали события, адаптивность и состояния loading / empty / error. Форму можно пройти без аккаунта; ошибки API сохраняют предпочтения и позволяют повторить запрос.

## Локальный запуск

Требуется Node.js 24+ — тесты запускаются встроенным TypeScript-раннером Node без дополнительных зависимостей.

```sh
cp .env.example .env.local
npm install
npm run dev
```

Откройте [localhost:3000](http://localhost:3000): проверенный JSON-каталог и локальные фото работают без API-ключа. Для вкладки новых событий Нью-Йорка и Planner добавьте `SERPAPI_KEY` (или существующий `API_KEY`) в `.env` либо `.env.local`. Ключ читает только сервер.

## Страницы

| Маршрут | Назначение |
| --- | --- |
| `/` | Главная и переход в Planner / Explore |
| `/planner` | Город → интересы → дата и предпочтения → проверка |
| `/planner/results` | До пяти рекомендаций, причины выбора и изменение предпочтений |
| `/explore` | Каталог, фильтры города / даты / категории и загрузка следующих страниц |
| `/events/[id]` | Детали, статус и ссылка на первоисточник |
| `/login`, `/register`, `/profile` | Переход сразу в `/planner`, без входа и регистрации |

Черновик и последний результат сохраняются в `sessionStorage` текущей вкладки. Обновление результатов восстанавливает последний ответ; прямой переход на `/planner/results` без сохранённого результата предлагает вернуться к форме. Повреждённые сохранённые данные не используются. При недоступном хранилище остаётся состояние в памяти до перезагрузки.

## Проверенный каталог

`src/data/catalog.json` содержит 113 вручную проверенных событий и регулярных программ: 18 категорий, все 50 штатов, Washington DC и 61 город. Проверка первоисточников — 14 ноября 2026. Вымышленные события из присланных demo-файлов не используются; из файла категорий сохранена таксономия с сопоставлением `games → gaming`, `food-drinks → food`, `arts-culture → art`.

У каждой записи есть официальный `sourceUrl`, `lastVerifiedAt`, `evidenceUrl` и краткое основание проверки `evidenceNote`. Изображения каталога лежат в `public/catalog`; исходные ссылки сохранены в `imageSourceUrl`. Фото площадки, организатора или прошлой редакции помечаются `imageIsIllustration`. Нажатие на карточку открывает страницу события с официальной ссылкой.

Фильтры идут в порядке категория → штат → город → дата. По умолчанию открыт весь каталог, поэтому каждая категория доступна без привязки к Нью-Йорку. Числа в списках показывают количество записей; в справочнике городов показываются только города с проверенными событиями. Washington DC доступен в списке отдельно от 50 штатов карты.

`src/lib/catalog.ts` содержит единые фильтры и географию. Для календаря используются только подтверждённые даты, `occurrenceDates`, `availableDateRanges`, `excludedDates` и сезонные/недельные ограничения. «Select dates» без списка дат не считается ежедневным расписанием. Просроченные датированные события скрываются. Неизвестная цена остаётся неизвестной. Это подборка по официальным страницам, а не полный каталог всех событий страны или гарантия наличия билетов.

Для обновления измените JSON и добавьте проверенное изображение в `public/catalog`, сохранив исходный URL и дату проверки. `npm test` проверяет полноту категорий/штатов, ссылки, наличие и формат всех фото, календарные исключения, фильтры, пагинацию и детали без обращений к SerpApi.

## Подключение backend

Контракт и типы находятся в `src/types/event.ts` и `src/types/planner.ts`, HTTP-клиент — в `src/lib/api.ts`. Встроенные Next.js Route Handlers в `src/app/api` используют проверенный каталог через `src/lib/server/catalog.ts` и live-адаптер `src/lib/server/serpapi.ts`. Отдельный Express-сервер и дополнительные зависимости не требуются.

Дополнительный поиск с `source=live` вызывает [SerpApi Google Search API](https://serpapi.com/events-results) (`engine=google`, `events_results`), детали загружаются через `google_event_details`. Поддерживаются `SERPAPI_KEY` и существующий `API_KEY`; первый имеет приоритет. `/api/health` возвращает `{ "ok": true }`. Live-поиск поддерживает New York, NY; основной JSON-каталог охватывает всю страну.

Ответы провайдера кешируются на 30 минут; одновременные одинаковые запросы объединяются. Кеш ограничен 100 запросами, неудачные ответы удаляются. Не более 30 новых обращений к провайдеру в минуту на процесс, таймаут каждого — 10 секунд. Кеш и ограничитель находятся в памяти одного процесса, сбрасываются при перезапуске и требуют общего хранилища перед запуском нескольких экземпляров.

Planner выполняет поиск по выбранным интересам и проверяет даты, время и бюджет без OpenAI. Для экономии квоты уточняются первые пять уникальных кандидатов; это ограниченная подборка, а не полный каталог. В расчёт попадают только даты с явно указанным годом; год и время не придумываются. Неизвестная цена не проходит ограничение бюджета, включая «только бесплатно». Дополнительные пожелания автоматически не интерпретируются. На главной показана подборка из проверенного каталога; признак `isMajor` не присваивается автоматически.

Выберите один способ подключения в `.env.local`:

- **Встроенный SerpApi:** оставьте обе переменные пустыми и задайте серверный ключ.
- **Серверный proxy:** задайте `API_PROXY_ORIGIN=http://localhost:8000`. Запросы браузера идут на локальный `/api`, Next.js перенаправляет их на backend; настройка CORS для браузера не нужна. Указывайте origin без `/api`.
- **Прямые запросы из браузера:** задайте `NEXT_PUBLIC_API_BASE_URL=http://localhost:8000`, оставив proxy пустым. Backend должен разрешать CORS для адреса фронтенда. Это публичный адрес, а не секрет.

После изменения env перезапустите dev-сервер; для production-сборки выполните сборку заново. SerpApi / Ticketmaster / OpenAI secrets нельзя помещать в `NEXT_PUBLIC_*` или клиентский код. Внешний proxy имеет приоритет над встроенными маршрутами.

### Контракт для интеграции

- `GET /api/events?state=NY&city=New%20York&date=2026-11-21&category=music&page=1` → `{ events, pagination: { page, pageSize, hasMore } }`. Город, штат, дата и категория необязательны; без них возвращается весь проверенный каталог с пагинацией по 12. `source=live` включает отдельный поиск SerpApi.
- `GET /api/events/:id` → `{ event }`; идентификатор источника кодируется через `encodeURIComponent`.
- `POST /api/plan` → `{ planId, summary, recommendations: [{ event, matchScore, reason }] }`, от 0 до 5 рекомендаций. Дополнительно поддерживается массив строк `suggestions`.
- Ошибки: `{ error: { code, message, details?: { field } } }`, с корректным HTTP-статусом.

Для дат frontend выбрал единый вариант контракта из ТЗ: **`startDate` / `endDate` включительно**, формат `YYYY-MM-DD`. Его необходимо использовать и в backend. Today / Tomorrow / This weekend рассчитываются по `America/New_York`; одиночная дата передаётся одинаковыми началом и концом. В воскресенье This weekend означает оставшееся воскресенье.

```json
{
  "city": "New York",
  "interests": ["music"],
  "startDate": "2026-11-21",
  "endDate": "2026-11-22",
  "budgetMax": 50,
  "timePreference": "evening",
  "notes": "Something relaxing"
}
```

`Any budget` полностью исключает `budgetMax` из запроса; `Free only` передаёт `0`. Пожелания ограничены 500 символами. Полная модель `EventData` обязательна: `id`, `source`, `sourceEventId`, `title`, `category`, `city`, `startAt`, `timezone`, `venue`, `address`, `description`, `imageUrl`, `priceMin`, `priceMax`, `priceKnown`, `currency`, `sourceUrl`, `status`. `startAt` и `sourceUrl` могут быть `null`; необязательные `dateText` и `priceText` сохраняют исходный текст SerpApi. Старые ответы Ticketmaster остаются совместимыми.

ISO-даты отображаются в часовом поясе площадки; даты без полного времени и часового пояса сохраняются как текст источника. Цены — в валюте источника или исходным текстом; без цены показывается `Price unavailable`. Для SerpApi разрешены HTTPS-ссылки исходных сайтов, для Ticketmaster сохраняется ограничение его доменом. Ссылки с логином, паролем, нестандартным портом и небезопасными протоколами отклоняются. Frontend не придумывает URL, адреса, цены, изображения событий или наличие билетов.

## Проверки

```sh
npm test
npm run typecheck
npm run build
```

Каталог: 43 автотеста, TypeScript и production build проходят. Дополнительно через запущенный локальный сервер проверены все 18 категорий, 51 регион (50 штатов и DC), 60 городов, 78 деталей и 78 изображений — HTTP 200. Браузерная автоматизация для этой правки была недоступна.

Тесты проверяют календарь New York и границы дат, валидацию формы, бюджет без лимита / нулевой бюджет, неизвестные цены, внешние ссылки, кодирование API-параметров, ошибки, отмену запросов и структуру ответа. Тестовые события существуют только в `tests`; каталог приложения использует данные API.

Предыдущая проверка SerpApi-интеграции: 37 автотестов, TypeScript и production build. На реальном SerpApi получены 10 музыкальных событий и 5 рекомендаций; в браузере проверены каталог и переход к деталям. Ключ проверен на отсутствие в клиентской сборке. При первоначальной проверке frontend в браузере на временном тестовом API пройдены выбор интересов, review, один POST при двойном нажатии, результат → детали, unknown price, ошибка и повтор без потери формы, пустая выдача и её восстановление после reload, фильтр категории, Load More и 404. На ширине 320 px проверено отсутствие горизонтального скролла формы, каталога, результатов и деталей; также проверен планшетный вид 800 px. После расширения каталога проверены переход AI → Explore с выбранным фильтром, все 50 штатов в select, поиск San по California и Coming soon для Los Angeles. На 1280 px проверена сетка категорий и загрузка всех 12 иллюстраций. Тестовый API не включён в исходники приложения. AI через OpenAI требует отдельного backend; реальные события доступны через встроенный SerpApi.

## Разделы каталога

На главной доступны проверенные события, все 18 категорий и навигация «штат → город». Категории открывают весь каталог; карта и справочник — проверенные записи выбранного штата/города. Ограничение Coming soon для каталога удалено; live-поиск остаётся отдельной возможностью Нью-Йорка.

После панорамы Нью-Йорка идут редакционная подборка Trending in New York, ближайшие события на 30 дней, категории и встречи Meet someone new. Для открытых встреч в каталоге используется признак `isSocial`. Карта расположена непосредственно перед футером. На карте подписаны все 50 штатов; Alaska / Hawaii показаны отдельными вставками. Карта и фильтр штата синхронизированы: выбор обновляет готовый список городов и сбрасывает фильтр города на «Все города». Выбор конкретного города оставляет в каталоге только его карточку. Штаты доступны мышью и клавишами Enter / Space; на узких экранах карту можно прокручивать горизонтально или пользоваться фильтром. Контуры сохранены локально из [US Atlas 3.0.1](https://github.com/topojson/us-atlas) в проекции Albers USA; лицензия — `public/maps/LICENSE-us-atlas.txt`. Внешний картографический сервис и API-ключ не требуются.

Категории Family, Books, Games, Technology, Food & Drinks, AI, Running, Arts & Culture, Climate, Fitness, Wellness, Crypto доступны вместе с прежними Music, Sports, Theater, Outdoors, Nightlife, Comedy. Нажатие категории открывает `/explore?category=...`; те же ID доступны Planner. Backend должен принять новые ID `family`, `books`, `ai`, `running`, `climate`, `fitness`, `wellness`, `crypto`. Картинки категорий сохранены в `public/categories` из предоставленных пользователем ссылок Luma; Family — со [страницы категории](https://luma.com/family?k=t).

Расширение Events API: необязательные query `state=NY` и `major=true`, а у Event — необязательное boolean-поле `isMajor`. Для блока крупных событий backend должен вернуть подтверждённые крупные мероприятия с `isMajor: true`, отсортированные по времени. Этот флаг сохранён для совместимости внешнего backend; на главной отображаются проверенные события без обещания крупного масштаба. При отсутствии API выводится ошибка с Retry, при отсутствии подходящих событий — empty state.

## Дизайн по референсу Fever

Главная, навигация, каталог, карточки, состояния и Planner оформлены по [Fever London](https://feverup.com/en/london): Montserrat, белые поверхности, синие акценты, кнопки с круглым контуром, фотоблок города и чипы интересов. [Разбор референса](docs/fever-design.md) содержит точные значения цветов, размеров, источники шрифта и фотографий. Montserrat хранится локально в `public/fonts` с лицензией OFL; запросов к Google Fonts из браузера нет.

Поиск в шапке открывает `/explore?q=...` и передаёт Events API необязательный query `keyword` (до 100 символов). Backend должен применить этот фильтр к событиям. Карточки подборок показывают фотографии из записей событий. Настоящие события, цены и рекомендации по-прежнему приходят только из API.
